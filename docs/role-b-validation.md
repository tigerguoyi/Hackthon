### 依赖与校验范围的真实记录

A 的 Git 中存在 `node_modules`，但缺少 AJV 的构建文件，首次原测试出现 4 项依赖错误。没有在 A 中安装或修补。B 的临时环境安装了锁文件指定的 AJV 8.17.1 与 ajv-formats 3.0.1；原 12 个 A 测试方法通过只读 harness 复用 B 校验子进程后通过。

桌面副本首次测试环境未将 Node 加入 PATH，4 项 Schema 子进程未启动；配置运行时 PATH，并仅在 B 安装缓存的锁定 AJV 依赖后，完整 50 项通过。网页启动本身仍无需 Node。

旧 B metadata 没有 A 新 Schema 必需的 `action_policy`。直接将 A 的新 metadata Schema 强套旧 B 数据会如实失败，因此**没有给旧原件补字段**：`validate:schema` 校验新的隔离数据集，`validate:legacy` 使用 B 原有一致性校验。这是数据版本边界，不是通过放宽 A Schema 掩盖缺失。

| 案例 | 新 B 的最高候选 | 焦点推演 | 四个假设结果 |
|---|---|---|---|

案例 B 的实际射门并未被模型自动判为最佳；案例 C 也不强制把历史回传排第一。A 自有 outcome 模型与 B 的目标、候选和尾值不同；对照见 `reports/fixture-comparison.json`。内部数值对照保留在 `.models/fixture-research.json`，静态服务拒绝公开点号目录。

三次拦截不能解释成 75% 拦截概率。静态线路到达近似与有加速度、第一触球终止的推演也可能产生差异；它们是公开的模型假设，不是观察到的另一条真实比赛。

## 本地运行与团队接口

在仓库内双击 `启动Ne_Generator.command`，或 `python3 server.py` 后打开 `/team-integration.html`。端口冲突时启动文件自动换端口。

主要接口为 `/api/role-b/analysis`、`/routes`、`/rollout`、`/actual`；canonical request 通过登记过的 snapshot_id 解析当前状态，客户端不提交未来帧或实际动作。公开候选没有 Q2、value_gain、scenario_weight、概率或 Softmax 字段。

模型 Agent 尚未连接：返回 `model_unavailable` 及已计算的候选，解释对象为 null，trace 为空；不会把本地模板冒充在线 Agent。旧研究页的数值和解释仍可用，新数据数值诊断仅由 `python -m role_b.diagnostics --case a` 在本地读取。

## 明确保留的限制

1. hold 与高球在公共契约中不支持，不赋予虚假的零价值或排名。
2. 没有已校准的弱脚、个体雷达成功率、空中对抗、完整多人策略或真实 C/Foundry Agent。
3. 来源画像仅用于支持／展示和质量提醒，不把描述性指数当作动作概率。
4. 带球记录没有事前方向时实际匹配未知；仍可比较标准化候选。
5. xT 继承源策略分布，两步取最大值可能乐观；反事实没有真实观测标签。
6. 测试证明结构、引用、隔离、数值回归和给定场景的一致性，不证明真实比赛反事实决策准确。

上游 `contracts.export_fixtures` 依赖 A 的独立 outcome 引擎，未装入 B；固定案例直接使用原文件，不能误用旧 B 生成器重导出它们。
