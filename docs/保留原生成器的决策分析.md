## 覆盖范围：明确保留缺失

原联赛有4场全场轨迹，其他36场只有60秒预览。

- 事件链识别的选择节点：50,145个。
- 有精确时刻轨迹：5,377个。
- 缺失全员决策状态：44,768个，不输出虚构快照、候选或分数。
- 被排除的自动带球：32,711段。正常接球和重启后的自动带球不是自主选择。

正常结束的传球和射门是选择；带球只有紧接已完成带球、且不是取消动作时才视为再次自主带球。已结束事件用于建立历史选择的索引，但结果和未来终点不进入对应的事前状态。传球对象来自历史选择，用来识别要评价哪个候选，不作为姓名或ID学习特征。

原预览以最后进球附近选择，存在后验抽样偏差。36场的预览预测只作单独标记的描述性展示，不进入空间概率模型拟合、温度校准或主测试。其余时间在 Coverage / conflicts 中保留入口。

## 新增数据及来源

输出根目录为 `data/league-enriched-v1/`：

| 目录或文件 | 内容 |
|---|---|
| `manifest.json` | 来源提交、规则、原始文件及生成器的SHA-256、每场覆盖 |
| `reconstruction/*.json.gz` | 所有节点与缺失原因；覆盖节点的精确原始状态镜像和源文件／帧引用 |
| `.models/fold-*.joblib` | 四折基线概率树、xT、拟合／校准／测试名单 |
| `matches/*/index.json.gz` | 全场覆盖索引、代表性节点、最大损失列表和温度 |
| `matches/*/scores-*.json.gz` | 每32个覆盖节点一块；候选、特征、概率、Q、分数、来源和防守诊断 |
| `reports/` | 字段映射、覆盖、训练、评分和资源报告；可选新文字报告 |
| `validation/` | 全量验收结果 |
| `.work/` | 中断可恢复的校准中间结果，不提交、不对HTTP公开 |

状态镜像保留解析原JSON数值，不转Float32；通过原文件、行／帧和时间引用核对。镜像是观测的副本，候选后继则是独立的模型预测，不能混称原始真实轨迹。

字段来源分为 `observed_original`、`derived`、`candidate_derived`、`model_prediction`、`retrospective_only`。原25项特征逐项映射，额外增加接收区最近防守距离、可达性、门将纵深、门将线路覆盖和状态质量，共30项。位置、速度、时间等原本存在，不是这次第一次生成。

压力、线路和到达时序是几何启发式，不是人体测量。没有身体朝向、注意方向、疲劳或真实意图。运动速度方向不能解释为身体朝向。

## 候选与历史动作的边界

每个持球状态生成每位队友一个标准化传球、三个带球方向和普通射门，含门将传球和远射。地面传球支持到35米，较长标准方案使用高球并支持到60米；超出距离／场地范围的不参与Softmax。35／60米是本版本支持边界，不是足球绝对极限。

候选接球点用当前队友位置和短时速度计算，持续时间使用固定计划速度，不能使用实际未来落点或实际结束时间。

历史传球若是超出地面支持范围的地面球，不会拿可执行高球替代后冒称其实际评分，而是保留原件并置空分数。带球原本没有保存完整的事前方向意图；当前以标准化向前带球表示动作类型，并持续标注 `type_only_standardised` 和解释限制。该数值不是对完全恢复出的精确带球方向的评分。

支持方案没有重复追加历史同名候选，避免重复项稀释偏好份额。不可评分显示空值，不用0分替代。

## 双层价值评估

### 原模拟一致性基线：B0 / B1

基线只解释7d0c193的简化世界，不把旧版不合理行为解释为正确足球。

- 传球老师标签来自旧公式：接收者距最近外场防守者不足8米时按球队传球／压迫参数降低成功率；否则为1。没有迁移旧决策版的老师或模型。
- B0用基础状态与候选参数，B1加入几何特征。两者使用 `HistGradientBoostingRegressor`：150轮、学习率.05、最多15叶、最少50样本、L2=1、不随机早停，种子20261021。
- 基线解析概率按保存的三位小数轨迹重算；8米阈值附近可能与原模拟器内部全精度值存在微小差异。实际传球及一个按事件ID确定的额外传球用于蒸馏。只有实际选择的样本检查真实抽样成败，额外标签不当作真实观测。
- 带球保有率为1：旧版没有被断机制，不能伪造负样本。
- 进球率采用旧版球队能力公式；射门无条件扑救率为.43，射偏为 `1-goal-.43`。只有100次完整轨迹射门，不训练高维射门树。
- 旧版不允许的射门位置和传给门将，在基线中标记Unsupported。

xT使用拟合比赛的全部原事件，统一攻向划为12×8格：射门率用2个全局分布伪样本、射门进球率用10个；转移核包含失败移动的分母质量。零初始化，变化小于1e-6或最多1000轮停止。

`V = P(shot)*P(goal|shot) + (1-P(shot))*T*V`

### 几何战术假设：B2 / B3

概率先验在 `enriched_rules.CONFIG` 及相邻纯函数中版本化，未拿它们生成比赛或训练“现实真理”。传球随距离、线路及接球压力增加而降低；带球随压力与接近速度增加而降低；射门随距离、角度、起点压力和门将线路覆盖变化。

射门先计算封堵，再在未封堵条件下计算进球、扑救、射偏，四项总和为1，封堵风险不重复扣除。远射概率可平滑趋近零，不沿用原决策版.002下限。

B2是一层动作展望加xT尾值；B3为两层，主分析用B3：

$$
V_0(s)=xT(s),\quad V_h(s)=\max_a Q_h(s,a)
$$

$$
Q_h(s,a)=\sum_z P(z|s,a)\left[r_z+e^{-\Delta t_z/120}\sigma_zV_{h-1}(\hat s'_z)\right],\quad h=1,2
$$

进球奖励1并终止，丢球切换对手视角取负号，半场／全场边界终止预测。后继仅按当前运动趋势做短时几何估计，不模拟整场比赛。传球价值可以包含队友接球后更好的射门，不能只看原行为分布下的xT。

这不是Fitted Q Iteration，不是自主踢球策略，也不声称经过真实足球训练。两步预测的跑位、接触和反应仍是近似，没有完整越位、碰撞、补射和多人协防模型。

默认、风险系数降低20%、提高20%三种假设分别评分；最高候选改变则显示Assumption-sensitive。波动不是统计置信区间，不根据推荐动作比例调参。

## 四折划分和验证含义

按比赛周形成四折，每折20场拟合、10场校准、10场测试：

- xT只用拟合部分的20场事件。
- 空间树只用拟合部分的两场完整轨迹。
- 温度和实际结果校准只用一场完整校准比赛。
- 主测试是一场完整测试比赛，其余该周预览仅作描述性推理。

每场显示使用其测试折，未参与该折拟合或校准。报告B0/B1软标签MAE、实际结果Brier和校准分箱；B2/B3报告价值排序变化、假设敏感性和场景方向。战术假设对旧结果拟合更好或更差都不能证明现实足球准确性。

## Softmax：所有选项合计100，不是最好选项100

$$
p_i=\frac{e^{(Q_i-Q_{max})/\tau}}{\sum_j e^{(Q_j-Q_{max})/\tau}},\quad Score_i=100p_i
$$

仅支持项进入分母，按key去重。所有支持项合计100；单个选项可以最高只有15、30或60分。相近价值接近均分，单一候选为100但不代表选择优异。

温度取独立校准状态全部可比较候选差距的90%分位数除以ln9，限制在.02–.20，无有效差距时取.05。它是显示尺度，不是行为概率校准，不逐节点调整。

例：Q为.12、.10、.08，温度.05，份额约47.2、31.6、21.2。页面显示一位小数，小于.1显示`<0.1`；内部保留精度。分数不是成功率、进球率、历史百分位或能力分。不同候选数量的节点不宜按分数直接比较球员。若14个方案等价，每项约7.1分，并不表示球员决策只有7.1%的质量；页面同时显示等分参考。

没有采用除以最大项再乘100，也没有min-max强制制造0分。不能通过softmax本身改变Q排序或修复射门偏差。

## 默认展示的多样性

Representative decisions最多20个，按球队和后场／中场／前场分层：每队优先3／3／4个。按已显示次数轮换球员，再考虑机会损失或威胁大小。

- 每人最多2个，每队最多10个。
- 每个球权回合最多1个，同一球员相隔至少30秒。
- 机会损失／模型偏好／接近选项全局分别最多10／5／5个。
- 排序依赖假设、历史选择无法评价的节点不进入代表性列表。
- 某层不足向该队其他层补充，仍不足就少显示，不伪造其他球员。

All covered decisions显示全部有状态节点及每人数量；Largest value losses明确为损失榜；Coverage / conflicts保留缺失、执行冲突和意图不可恢复说明。基线比较单独显示B0、B1与主层的价值和排序。

没有射门推荐硬配额，也没有传／带／射数量配平。场区和球员覆盖是展示抽样约束，底层全部推荐分布保持可审计。

## 防守诊断和本地工具

防守保持独立一秒局部诊断：最多三名关键防守者，对保持趋势、上抢、封线、盯防、回撤做加速度有界的位移，使用连续平均速度积分；从静止以3.5m/s²加速一秒的位移为1.75米，而不是3.5米。

诊断比较一层战术威胁的降低，和主持球两步价值不同，不套Softmax也不合并能力评分。投影仍是近似单人调整，不是真实避免失球数。

本地查询函数：`get_decision_context`、`compare_candidates`、`get_constraints`。无在线Agent或Key依赖，解释模板只使用已保存证据、输入、规则和结果版本。

## 重现流水线

建议Python3.12，离线依赖单独安装；普通网页不需要这些依赖。

```sh
python3 -m venv .venv-enrichment
source .venv-enrichment/bin/activate
python -m pip install -r requirements-enrichment.txt
export LOKY_MAX_CPU_COUNT=4
python enriched_pipeline.py audit
python enriched_pipeline.py train
python enriched_pipeline.py score
python enriched_pipeline.py validate
```

或 `python enriched_pipeline.py all`。`score --match PL26-W01-MCI-CHE` 可生成单场评分，但温度仍需四场校准准备。不要在仅审计单场后直接训练；训练要求全部40场审计索引。查询示例：

```sh
python enriched_pipeline.py explain --match PL26-W01-MCI-CHE --decision e001335
```

原始目录及其祖先不能作为输出目录。审计前后、评分前后和最终验证均核对原件哈希。新报告接口：`GET /api/match-report?dataset=enriched-v1&match_id=...`；原POST接口接受original/enriched-v1白名单，生成报告位于独立的`reports/narration/`。
